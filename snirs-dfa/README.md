# SNIRS DFA — собственный сканер для СНИРС

Все файлы реализации SNIRS DFA, тесты, документация и сборка находятся в
`snirs-dfa/`. Общие исходные материалы проекта остаются на уровень выше;
используется единый заголовок `../scanner.h`.

Реализация второго пункта плана на **C++17** по `../scanner_spec.txt`.
В плане и спецификации указан C11; здесь язык реализации C++ выбран по заданию
пользователя. Общий `scanner.h` сохранён без изменений, библиотека доступна
из программы на C11 через C ABI. Реализации flex и re2c в этот пункт не входят.

Получены два объекта с одинаковыми операциями `open`, `next`, `close`:

| Объект | Вычисление функции переходов δ |
| --- | --- |
| `scanner_table` | Индексация таблицы по состоянию и классу входного байта (§ 2.6.1) |
| `scanner_branch` | Вложенные `switch` по состоянию и классу входного байта (§ 2.6.2) |

Оба варианта получены из одного описания ДКА. Чтение входа, запоминание последней
заключительной позиции, выбор максимальной лексемы и обработка результата
реализованы один раз: `scanner_next<Transition>` в `table/scanner_table.cpp`.
Параметр шаблона задаётся при компиляции; переключения варианта внутри цикла нет.

## Сборка и проверка

Все команды ниже выполняются из папки `snirs-dfa` (сначала `cd snirs-dfa`
из корня проекта). Результаты сборки помещаются в `snirs-dfa/build/`.

Нужны компилятор C++17 и CMake 3.16+. Скомпилированный сканер не зависит от Python,
flex, re2c и сторонних библиотек. В тестовой сборке также нужен компилятор C11.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

В Windows с MinGW, если CMake по умолчанию выбирает другой компилятор:

```powershell
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
```

Для сборки только библиотеки добавьте `-DBUILD_TESTING=OFF`.
При подключении к другому CMake-проекту используйте цель `snirs_dfa`.
При ручной сборке добавьте `table/scanner_table.cpp` к исходникам программы,
например `g++ -std=c++17 -O2 main.cpp table/scanner_table.cpp -o main`.
Программу на C компилируйте C-компилятором, а окончательную компоновку выполняйте
C++-компилятором, чтобы подключить его стандартную библиотеку.

## Использование

Для C++ включайте `table/scanner_table.h`: он оборачивает неизменённый общий
интерфейс в `extern "C"` и дополнительно объявляет `scanner_branch`.
Его следует включать вместо прямого включения `scanner.h`.
Из C можно включать исходный `scanner.h` для `scanner_table` или расширенный
заголовок для доступа к обоим вариантам.

```cpp
#include "table/scanner_table.h"
#include <cstdio>

int main() {
    // Ровно шесть байтов: завершающий ноль не требуется.
    const unsigned char text[] = {'i', 'f', ':', '=', '1', '5'};
    const Scanner &scanner = scanner_table; // или scanner_branch
    void *state = scanner.open(text, sizeof text);
    if (!state) return 1;

    for (;;) {
        const Token token = scanner.next(state);
        std::printf("%d [%zu,%zu)\n", static_cast<int>(token.kind),
                    token.begin, token.end);
        if (token.kind == TOK_EOF || token.kind == TOK_ERROR) break;
    }
    scanner.close(state);
}
```

Результат по видам: `TOK_IF [0,2)`, `TOK_ASSIGN [2,4)`,
`TOK_NUMBER [4,6)`, `TOK_EOF [6,6)`.

`open` хранит указатель и длину входа, выделяя только состояние экземпляра.
При нехватке памяти возвращает `nullptr`; при ненулевой длине и нулевом указателе
тоже возвращает `nullptr`. Буфер должен оставаться доступным и неизменным
до `close`. Пустой вход допускает нулевой указатель.

Сканер читает только байты с индексами меньше `length`, не изменяет и не
освобождает вход. Он не читает файлы и не печатает сообщения. Координаты —
байтовые полуинтервалы `[begin,end)`, отсчёт с нуля. Комментарии и пробелы
пропускаются. После первого `TOK_ERROR` или `TOK_EOF` экземпляр запоминает
этот результат и возвращает его при каждом следующем `next`.
Независимые экземпляры можно использовать одновременно; один экземпляр
не следует вызывать одновременно из нескольких потоков.

## Автомат и соответствие теории

Подробное формальное описание: [table/automaton.md](table/automaton.md).
Там заданы A, Q, q₀, F, классы байтов, метки заключительных состояний и примеры путей.

| Файл | Содержимое |
| --- | --- |
| [table/generate_dfa.py](table/generate_dfa.py) | Единое описание переходов и генератор представлений ДКА |
| [table/automaton.dot](table/automaton.dot) | Полный граф в формате Graphviz, дуги в Q_DEAD опущены |
| [table/transitions.tsv](table/transitions.tsv) | Полная таблица δ: состояния × классы байтов, с метками состояний |
| [table/dfa_generated.h](table/dfa_generated.h) | Таблица δ, вариант с ветвлениями, классы байтов и метки |
| [table/scanner_table.cpp](table/scanner_table.cpp) | Общий алгоритм сканирования и определения обоих Scanner |

Автомат имеет 61 состояние, включая поглощающее `Q_DEAD`, и 36 классов байтов.
Классы объединяют только байты с одинаковыми переходами из **всех** состояний.
Таблица δ занимает 2196 байт, классификация байтов — ещё 256 байт.
Граф не минимизирован: отдельные состояния префиксов ключевых слов сохранены
для понятного разбора путей. Ключевые слова распознаются самим ДКА.

Для `if` путь заканчивается в `Q_KW_IF` с меткой `TOK_IF`. Для `if2`
следующий переход ведёт в `Q_IDENT` с меткой `TOK_IDENT`. Достижение
заключительного состояния не завершает поиск: алгоритм продолжает читать,
сохраняя последнюю заключительную позицию и её метку. При переходе в `Q_DEAD`
или конце входа выбирается эта позиция. Если заключительного состояния не было,
выдаётся `TOK_ERROR` на первом байте фрагмента.

Состояние комментария допускает любые байты, включая `0x00` и `0x80–0xFF`,
кроме CR/LF. Конец массива проверяется отдельно; ни один байт не используется
как маркер EOF. Сложность прохода O(N), дополнительная память экземпляра O(1).

При изменении описания пересоздайте производные файлы (Python 3.10+):

```sh
python table/generate_dfa.py
python table/generate_dfa.py --check
```

Генерация детерминирована; `--check` проверяет актуальность без записи.
При наличии Graphviz граф можно отрисовать командой
`dot -Tsvg table/automaton.dot -o build/automaton.svg`.

Для опыта Б следует собирать оба варианта одним компилятором и с одинаковыми
флагами. Оптимизатор может преобразовать `switch` в собственные таблицы или
другие конструкции; при интерпретации замеров учитывайте фактический машинный код.

## Что проверяют тесты

`tests/scanner_tests.cpp` сравнивает оба варианта с независимым процедурным
эталоном по видам **и** границам всех лексем. Проверяются 81 685 входов:
ручные примеры, все одно- и двухбайтовые комбинации, префиксы и продолжения
ключевых слов, ошибочные байты после правильных лексем, комментарии,
длинные лексемы и воспроизводимые случайные последовательности.

Дополнительно проверяются все переходы обоих представлений δ,
повторные терминальные результаты, независимость экземпляров, ранний `close`
и буферы без завершающего байта, размещённые перед недоступной страницей памяти.
На Windows и POSIX входная страница также защищена от записи.
`tests/c_interface_test.c` проверяет компоновку и вызовы из C11 через исходный
`scanner.h`. Если доступен Python, CTest также проверяет актуальность генерации.
