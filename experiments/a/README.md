# Эксперимент А: четыре сканера

Фактические результаты: [RESULTS.md](RESULTS.md). Подробные условия и первичные
данные каждого сеанса находятся в `results/<run_id>/`; рабочая копия —
`build/results/<run_id>/`.

Запуск из корня проекта:

```sh
python experiments/a/run_experiment.py
```

Либо `./build.sh a` из shell. Раннер собирает Release, проверяет контрольные
примеры и полную выдачу всех четырёх сканеров, проверяет SHA-256 входов Б,
затем проводит основной сеанс. Отдельные варианты не запускаются параллельно.
Существующие результаты Б сохраняются без изменений.

Нужны CMake, Python 3.10+, GCC/G++, flex и re2c. Можно явно указать генераторы:

```sh
python experiments/a/run_experiment.py --flex /path/to/flex --re2c /path/to/re2c
```

В Windows также используются локальные пути `build/tools/winflexbison/win_flex.exe`
и `build/tools/re2c-build/re2c.exe`, если генераторов нет в PATH.
При данном запуске использованы [WinFlexBison 2.5.25](https://github.com/lexxmark/winflexbison/releases/tag/v2.5.25)
(flex 2.6.4) и [re2c 4.6](https://github.com/skvadrik/re2c/releases/tag/4.6).
Загруженные архивы и исполняемые файлы имеют записанные в environment.json SHA-256.
re2c собран из официального исходного архива с помощью CMake и MinGW:

```sh
cmake -S build/tools/re2c-4.6 -B build/tools/re2c-build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DRE2C_BUILD_TESTS=OFF
cmake --build build/tools/re2c-build --target re2c --parallel 4
```

Все исходные лексические правила остались прежними. flex генерируется с
`-8 -Cf`; re2c — без дополнительных настроек командной строки, правила и
режим контроля конца буфера содержатся в `re2c/scanner.re`.

Для измерения А используется функция цикла и checksum из
`experiments/common/benchmark.c`, общая с Б. Сохраняется прежняя точка входа Б;
А передаёт расписание из четырёх порядков и включает формат experiment_results.txt.
Для `experiment_results.txt` внесена ровно оговорённая инструкцией А поправка:
перечень участников А дополнен branch.

Основные файлы сеанса:

- `run.txt` — статус, дата, условия, версии, флаги, команды, checksum и рецепты.
- `measurements.csv` — строго заданные 10 столбцов, 640 строк, время целыми наносекундами.
- `summary.csv` — строго заданные 9 столбцов, 40 строк, медианы и квартильный разброс.
- `validation.csv`, `preflight_validation.csv` — полная сверка каждого входа с эталоном до EOF.
- `inputs.json` — N, K, SHA-256, рецепты, распределения видов, доля пропусков и соответствие Б.
- `coverage.json` — фактическое покрытие видов на нагрузках.
- `textbook_inventory.json` — 72 фрагмента подготовленного корпуса, строки и подтверждённые параграфы.
- `source_snapshot.zip`, `source_hashes.json`, `environment.json` — снимок версии и параметры сборки.

Исходные файлы — один учебный и девять искусственных. `textbook_long` из Б в
этот набор не включён: время исходного учебного текста существенно больше
пустого интервала часов. Исходный учебный корпус не изменялся и не размножался.
Для синтетических входов использованы те же байты, что в Б, с именами из инструкции А.

Монотонный таймер охватывает только цикл next и учёт результата. Подготовка,
open/close, копирование буфера, чтение, сверка и CSV не входят. Один прогрев
на вариант и файл, 16 раундов. Порядок из инструкции повторяется четыре раза,
так что каждый сканер занимает каждую позицию ровно четыре раза.

Checksum: uint64, начальное значение 14695981039346656037. Для каждого Token,
включая EOF, по очереди обрабатываются kind, begin, end: XOR значения поля,
затем умножение на 1099511628211 по модулю 2^64. K не включает EOF. Это та же
процедура, что используется в Б.

Пересчёт статистики из сохранённых измерений, без нового запуска сканеров:

```sh
python experiments/a/summarize.py experiments/a/results/<run_id>
```

Для пересоздания отчёта добавьте `--report experiments/a/RESULTS.md`.
Квартили — линейная интерполяция в отсортированном ряду по (n−1)p.
Скрипт проверяет число строк, расписание, хеши входов, K и checksum, прежде
чем создавать сводку. Сеанс с ошибкой получает status=ABORTED и не публикуется
как завершённый. Предыдущие сеансы не перезаписываются.
