# Наблюдения по опыту Б

## Что менялось

Для каждого входа сравниваются две реализации одного ДКА. Table берёт
следующее состояние из массива, branch выбирает его вложенными switch.
Начальное состояние, классы байтов, метки заключительных состояний,
алгоритм выделения самой длинной лексемы и сами переходы δ общие.
Проверка перебирает 61 состояние × 256 байтов. Между семействами
меняется состав или размер входа. Внутри пары байты одинаковы.

Например, ifx проходит через состояния префиксов i и if, а на x
переходит в обычное состояние идентификатора. Abx попадает туда
уже на a. Оба слова выдают один TOK_IDENT с одинаковыми границами.
Это позволяет менять путь по ДКА при сохранении результата сканирования.

## Где задана лексика

Общая для А и Б лексика зафиксирована в [scanner_spec.txt](../../spec/scanner_spec.txt).
Её классы описываются регулярными выражениями. Идентификаторы —
[A-Za-z][A-Za-z0-9]*, числа — [0-9]+. Ключевые слова и знаки заданы
конечными списками, пробельные символы и комментарии — правилами
пропуска. Оба собственных варианта распознают одну и ту же лексику.

[Генератор ДКА](../../snirs-dfa/table/generate_dfa.py) строит переходы
напрямую по этим правилам. Для ключевых слов и знаков строятся деревья
префиксов, для идентификаторов, чисел и пропусков явно задаются
состояния и петли. Из этого описания получаются таблица и код ветвлений.
Общего преобразователя регулярных выражений в ДКА в этой реализации нет.
Регулярные выражения в Python-генераторе нагрузок используются отдельно,
для независимого расчёта ожидаемых лексем.

В плане есть дополнительный опыт с добавлением ключевых слов,
которых нет во входе. Он исследовал бы размер автомата при фиксированном
входе. В основном опыте Б этот параметр не менялся.

## Что показал прогон

На учебном корпусе table дал 5,125 нс/байт, branch — 4,222 нс/байт.
Медиана парного отношения table/branch составила 1,225 [1,204; 1,285].
На идентификаторах длиной 128 байт отношение выросло до 4,357,
а на самом большом смешанном входе составило 0,752 в пользу table.
Для двухбайтовых чисел типичный разрыв был существенно меньше, чем
для длинных идентификаторов. Поэтому преимущество зависит от состава
входа и конкретной сборки. Эти замеры сами по себе не отделяют влияние
оптимизаций switch, кеша и предсказания ветвлений.
